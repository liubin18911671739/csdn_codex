# 第1章：安装 Codex，跑通开发环境

## 一、本章学什么，交付什么

这一章集中学习CLI 与 IDE、Python 解释器、工作目录。我们完成的任务是：确认版本、目录和读写能力，生成 environment.md。不用真实账单，避免把私人收支交给尚未核实的流程。

## 二、先看任务路线

```mermaid
flowchart TD
 A[安装并登录CLI] --> B[检查Python版本]
 B --> C[进入独立练习目录]
 C --> D[读取输入并新建文件]
 D --> E[人工核对路径和内容]
```

这个流程先确认解释器和目录，再做读写练习。环境记录文件来自真实运行；安装与登录没有重新操作，因此不在动图的验证范围内。

## 三、准备环境与练习材料

Windows 操作待实测，本机验证不能代替读者环境。CLI 安装按官方页面选择当前系统路径。npm 路径需要先安装 Node.js，确认 npm 可用后再执行：

```sh
npm install -g @openai/codex
codex --version
python3 --version
```

Windows 解释器可能使用 python 或 py -3，后续固定采用本机已验证成功的命令。不要混用 WSL 和原生路径。运行 codex 后按客户端完成登录，版本号不证明账号可用。IDE 用户从官方链接安装扩展、核对发布者、打开练习目录并独立确认登录。

本章从空目录开始，只创建 UTF-8 的 input.txt，内容为“环境练习”。不需要提前复制收支工具。

## 四、把任务交给 Codex

```text
只操作当前练习目录，不访问其他项目、账号配置或私人文件。只用Python标准库，不安装依赖，不使用浏览器、桌面控制或网络工具。先简述计划，再真正执行命令，中文回复简短。不能运行时如实说明，不伪造输出。已有目标不要覆盖。

读取input.txt；实际运行codex --version和python3 --version，只新建environment.md，写入输入内容与实际版本。用Python重新读取验证文件与输入一致，报告结果。
```

这里限定目录是为了减少无关修改，要求先阅读则让计划有输入依据。文字要求不能代替操作系统权限，实际授权仍需检查。

在空目录创建 input.txt，内容写“环境练习”。要求 Codex 读取并只新建 environment.md，记录看到的文字和真实执行的版本命令；不能运行的命令写明原因，不猜测版本。重新打开文件，核对文字及目录，然后再进入第二章。

## 五、追问和纠错怎么写

```text
先暂停修改。说明当前结果与预期的哪一项不符，给出输入行和代码依据。只修复已确认的问题，保留失败样例，不修改预期来适配错误结果。修复后重新检查全部相关项。
```

若模型提出安装第三方库，先要求解释标准库无法完成的部分。若只是路径错误，回到工作目录核对，不要扩大到整个磁盘。已有输出应换新名字保存，不能为了继续而自动覆盖。

## 六、迁移练习与验收

```text
我要换用自己的合成数据。请先列出字段、金额、日期及输出约束中需要确认的问题，等我确认后再改。保留旧版本和测试输入，解释每一项新行为。
```

重新打开 environment.md，核对输入原文和实际版本，确认 input.txt 未变、没有无关文件。把练习换到另一个空目录再试；不要删除旧文件来制造一次“首次运行”。
