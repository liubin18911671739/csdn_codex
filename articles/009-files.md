# Windows 文件整理实战：让 AI 写脚本，先预览，再批量处理

文件一多，改名就不再是一个轻松的小动作。你可能只是想加个项目前缀，处理完才发现规则不对：原来的名字是什么？哪些文件已经改了？还能不能退回去？

这一篇，我们先把任务收小：只拿三个测试文件，复制到一个新文件夹，并给副本统一加上“整理_”前缀。原文件保持原位。这样即使规则不合适，也可以回到原件重新开始。

**试读说明：配套脚本已在 macOS 的 Python 3.12 合成数据上检查；本文 PowerShell 命令及 Windows 文件系统行为待实测。无需第三方 Python 包。**

## 一、为什么先复制，不直接改名

批处理的难点常常在出错以后。直接改名需要保存旧名与新名的对应关系，还要考虑中途失败后怎样恢复。对于第一次练习，用一份新副本承接结果更容易检查。

这里的代价是多占一份存储空间。因此，本案例适合普通文件的整理练习，不应该直接拿整个系统盘或唯一备份来试。

脚本有三个约束：默认只显示计划；只有加上 `--apply` 才复制；输出目录已经存在就拒绝执行。它只处理输入目录直接包含的普通文件，跳过子目录与符号链接。

## 二、先准备一个看得懂的测试目录

配套脚本位于 `examples/organize.py`。如果只拿到了本文，请先取得随文示例文件，确认它保存在该位置。

假设你把项目保存到 `C:\AIWork\csdn`，打开 PowerShell 后进入项目根目录。下面路径是示例，请按实际保存位置修改：

```powershell
Set-Location "C:\AIWork\csdn"
New-Item -ItemType Directory -Path ".\examples\work\input" -Force
Set-Content -LiteralPath ".\examples\work\input\会议.txt" -Value "会议记录样例" -Encoding UTF8
Set-Content -LiteralPath ".\examples\work\input\报告.txt" -Value "报告样例" -Encoding UTF8
Set-Content -LiteralPath ".\examples\work\input\预算.txt" -Value "预算样例" -Encoding UTF8
```

这些写入命令仅用于新的练习目录。如果同名练习文件已经存在，会重写它们的内容，不要将路径替换为真实资料目录。

运行后，先在资源管理器里打开三个文件。每个文件内容不同，才便于发现复制错位。若你不熟悉命令行，也可以用记事本手动创建这三个文件，注意显示扩展名。

## 三、第一遍只看计划

先确认 `py -3 --version` 能返回版本号，再执行：

```powershell
py -3 examples/organize.py examples/work/input examples/work/output
```

如果你的电脑只有 `python` 命令可用，将 `py -3` 整体替换成 `python`。不要改变脚本和路径参数。

终端应显示三组对应关系，顺序可能与下面不同：

```text
会议.txt -> 整理_会议.txt
报告.txt -> 整理_报告.txt
预算.txt -> 整理_预算.txt
```

这一步不应生成 `output` 目录。请检查输入文件数量与计划是否一致，再看前缀是否符合要求。箭头右侧是将来副本的名字，不是已经完成的操作记录。

如果显示 `target already exists`，说明输出位置已有内容。换一个新的目录名，例如 `output-v2`，不要为让程序继续运行而删除不明文件。

## 四、看清楚以后，再执行复制

计划确认后，在同一条命令末尾增加执行开关：

```powershell
py -3 examples/organize.py examples/work/input examples/work/output --apply
```

输出目录应包含三个带前缀的文件，以及 `manifest.json`。清单记录原名与新名的对应关系，方便核对。

脚本中负责复制的关键语句是：

```python
shutil.copy2(x, t / plan[x.name])
```

`x` 是原文件，`plan[x.name]` 是新名称，`t` 是目标目录。完整脚本还负责参数检查、生成计划和保存清单，不能只复制这一行就当成可运行程序。

`copy2` 会尝试保留部分文件元数据，但不是完整的 Windows 权限与特殊数据备份方案。普通文本练习可以用它理解流程，重要资料的备份仍应使用适合其要求的方案。

## 五、用内容核对结果，不只看有没有文件

先检查文件名与数量，再打开副本对照原文。还可以用 PowerShell 计算一对文件的 SHA-256：

```powershell
Get-FileHash -LiteralPath ".\examples\work\input\报告.txt" -Algorithm SHA256
Get-FileHash -LiteralPath ".\examples\work\output\整理_报告.txt" -Algorithm SHA256
```

两项 Hash 值应一致，其余两对也按同样方法核对。这项检查针对文件字节内容，不代表访问权限等元数据也相同。

最后回到原目录，确认三个原件的名称与内容保持不变。不要因为终端没有报错，就省掉这一步。

## 六、中途失败怎么办

**只复制出一部分文件。** 可能是空间不足、权限不足，或源文件在执行时发生变化。输出目录不是事务，失败时可能留下部分成果。原件仍在，先查失败原因，再使用新的输出目录重试。

**重复执行报错。** 这是预期行为。当前脚本不合并目录、不覆盖旧结果，也不会把第二次运行伪装成增量同步。

**子目录没有处理。** 这是本篇的范围限制。递归处理需要重新设计目录映射，不能只把遍历函数换一下就投入真实资料。

练习完成后，若不需要这些副本，可以在资源管理器中将明确的练习输出目录移到回收站。不要从本案例推导出自动删除真实目录的命令。

## 七、怎样让 AI 继续改造这个工具

可以给 AI 这样一份新要求：

```text
请阅读 organize.py，再提出按年份归档的改造方案。
先说明年份来自文件名还是修改时间，不要擅自选择。
保留默认预览，拒绝覆盖，不删除原件。
先给出测试输入和预期输出，再修改代码。
```

年份从哪里来，决定了分类是否正确。这类业务规则值得你亲自决定。AI 可以帮忙实现规则，结果仍要拿测试文件核对。
