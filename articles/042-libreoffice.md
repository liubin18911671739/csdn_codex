# 用 LibreOffice 替代付费办公软件：先迁移三份文件，再决定换多少

准备换办公软件时，最容易想到的是安装：下载一个免费替代品，把原来的软件卸掉，事情似乎就结束了。

真正需要花时间的，往往是下一步。文档打开后多出一页，表格数字看起来正常却没有重新计算，演示文稿在自己的电脑上好好的，换台机器标题却跑出文本框。

所以，这一篇我们不急着搬走所有资料。先选一份文档、一张表格和一套演示，做一次小范围迁移。看清哪些工作已经能完成，再决定迁移的范围。

**试读说明：目标环境为 Windows。本文完整流程待 Windows 实测；此前 macOS 环境中的显示设置经验不等于 Windows 兼容性结论。**

## 一、先认识三个工具，再准备测试副本

LibreOffice 中，Writer 用于文档，Calc 用于电子表格，Impress 用于演示。它们分别承接常见办公任务，但这不等于能原样还原所有专有功能。

选三个有代表性的文件：文档最好包含标题与表格；电子表格包含真实业务会用到的公式和图表；演示包含图片、文字及实际使用的动画。全部复制一份作为测试材料。

若仍可使用原软件，先导出参考 PDF，再记录原文件的软件版本、页数或幻灯片数、关键数据结果。PDF 便于对照版式，不能替代表格公式与演示动画的测试。

## 二、从官方来源安装，先保留原来的工作方式

从 [LibreOffice 官方下载页](https://www.libreoffice.org/download/download-libreoffice/) 获取适合 Windows 的安装包。记录版本号和安装日期，便于后续定位差异。

按安装程序提示完成安装。选项可能随版本变化，涉及默认打开方式时先保留原设置。这样测试期间仍能用原来的工具处理急件，不会因为一次试用打乱整个工作环境。

安装后先打开 Writer，输入两行中英文，保存成 ODT。再另存一份 DOCX，关闭后分别重新打开。重点看文字、标点与段落是否一致。如果出现格式提示，先读清含义，再选择输出格式，不要覆盖原始资料。

ODT 可以作为在 LibreOffice 中继续编辑的工作文件；对方需要 DOCX 时，另行导出并复查交付版本。最终交付什么格式，应由协作要求决定。

## 三、把编辑背景调成自己舒服的颜色

长时间看文档，可以先调整应用显示偏好。在 Windows 菜单界面中，进入“工具 → 选项 → LibreOffice → 外观”；其他版本可能把相关设置放在“应用程序颜色”中。

本文给出一组可试用的颜色：

| 设置项 | 色值 |
|---|---|
| 文档显示背景 | `#CCE8CF` |
| 周围编辑区背景 | `#B7D7BB` |

在颜色自定义项目里分别查找对应项。若启用了“使用白色文档背景”，它可能覆盖主题里的文档颜色；需要取消该选项才能观察主题配色。若 Writer 的编辑区使用了背景图片，也要先关闭该效果。

这里调整的是应用外观，不是文档的页面填充。设置完成后查看打印预览，再导出一份测试 PDF，确认交付内容的背景符合预期。若具体文件本来就有页面填充，需要单独检查，不能指望主题设置把它清除。

绿色只是个人视觉偏好，不应宣称能治疗眼疲劳。屏幕亮度、环境光和休息同样需要关注。

## 四、文档兼容：逐页检查，比页数更重要

用 Writer 打开文档副本，与参考 PDF 并排对照。先看标题、段落、字体，再检查页眉页脚、脚注、目录和跨页表格。

例如，一份十页报告仍显示十页，最后一行表格却挤进页脚，这就不能算通过。页数是线索，页面里的内容才是检查对象。

如果出现字体替换，先确认目标机器是否安装了所需字体，以及是否具有使用权限。不要立刻逐段缩小字号去“凑页数”，否则可能掩盖真正原因。

完成调整后另存新文件，重新打开一次，再检查导出的 PDF。把发现的问题写入兼容记录，避免下次处理同类文件时从头猜。

## 五、表格兼容：先盯住关键结果

用 Calc 打开表格副本，优先找出会影响工作判断的单元格：总金额、日期、比率、汇总指标，以及引用外部数据的位置。

先记录原软件算出的基准值，再查看替代环境中的公式和结果。重新计算后逐项比较，检查筛选、图表和日期显示。仅看到单元格里有数字，不能证明公式已经正确执行。

含宏、加载项或外部连接的文件应单独测试。打开时不要为了消除提示就随意启用陌生宏。功能依赖无法满足时，先记录为暂不迁移项。

## 六、演示兼容：一定要播放一遍

Impress 打开演示副本以后，逐页检查标题位置、文本框溢出、图片裁切、图表及备注。然后进入实际放映，查看动画、转场和媒体。

编辑界面里看起来没问题，不意味着播放时就一定完整。对方只需要静态阅读时，可以另交 PDF；需要动画与现场讲解时，PDF 就不能替代放映测试。

如果会在另一台设备上演示，最终检查应在那台设备上完成。尤其是字体和嵌入媒体，不要等到上台才发现差异。

## 七、给迁移一个可以执行的结论

建议建立下面这份记录，而不是简单写一句“兼容良好”：

| 文件 | 检查项目 | 结果 | 下一步 |
|---|---|---|---|
| 报告副本 | 跨页表格与页脚 | 待测试 | 逐页对照 PDF |
| 表格副本 | 关键公式及重算 | 待测试 | 对比基准单元格 |
| 演示副本 | 字体与放映 | 待测试 | 在交付设备播放 |

上表是测试模板，没有填入虚构的实测成绩。完成后，将文件划为可直接迁移、调整后迁移、暂时保留原工具三类。分类依据是具体任务能否完成，不是软件品牌偏好。

开源替代可以一步一步推进。普通文件先建立稳定流程，复杂文件保留原件和回退路径。等三份代表文件的检查都有结论，再扩大范围，心里会踏实得多。
